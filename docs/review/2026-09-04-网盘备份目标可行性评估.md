# 网盘备份目标（百度 / 夸克）可行性评估

- 日期：2026-09-04
- 范围：为 `IFileStorage` 体系新增第三、四种网络输出目标（当前仅 `Smb` / `WebDav`）
- 结论摘要：**百度网盘可以做，但有两条硬约束（应用沙箱目录、单文件大小）会改变产品形态；夸克网盘没有公开 API，不可做**。另外，网盘备份的传输时长比局域网 SMB 慢 1~2 个数量级，**必须先完成后台化（前台服务）才能用**，两者是耦合的而非独立功能。

---

## 1. 结论先行

| # | 结论 | 依据 |
|---|------|------|
| 1 | **百度网盘：可行**。官方开放平台、文档齐全、个人开发者可实名后创建应用、支持 OAuth 三段式分片上传与秒传 | `pan.baidu.com/union/doc`（创建应用页更新时间 2026-08-03） |
| 2 | **百度硬约束 A（沙箱目录）**：**按官方文档用应用身份调 API**，只能读写 `/apps/{应用名称}/`。但伪装官方客户端 UA 可绕开实现全盘访问（OpenList 即如此，见 §9） | 官方创建应用页 + §9 调研 |
| 3 | **百度硬约束 B（单文件大小）**：普通用户 4GB / 会员 10GB / 超级会员 20GB，且分片数不超过 1024 个；另有类型限制（视频、Live Photo 在网盘 APP 端受限，需实测 API 端是否同样受限） | 官方文档转述（多来源一致） |

| 5 | **应用凭证不能随包分发**。本项目 GitHub Release 公开分发 APK（NFR-A10），AppKey/SecretKey 内嵌等于公开泄露，会被盗用限流。必须由用户自己申请、自己填进设置页 | 架构约束 |
| 6 | **网盘备份必须依赖后台化**。20GB 数据：局域网 SMB 约 16 分钟；网盘全量 @5MB/s 约 68 分钟、@500KB/s 约 11 小时。**没有前台服务与断点续传就无法落地** | 见 §5 |
| 7 | **秒传是网盘方案的真正价值**：内容未变的文件命中秒传后只需 2 次 API 调用，增量备份从小时级降到分钟级。本项目原样复制不转码，**与秒传天然适配** | 百度 `precreate` 返回 `return_type=2` 即命中秒传 |
| 8 | 建议：**百度网盘纳入规划；夸克放弃；第四个目标优先选标准协议（S3 兼容 / WebDAV）而非再接一家私有 API** | 见 §4 |
| 9 | **【补充，见 §9】最优解可能是根本不自己接：部署 OpenList 作中转，用已实现的 `WebDavFileStorage` 直连，零新代码覆盖几十种网盘** | §9.4 选项 B |
| 10 | **【修正，见 §9】沙箱不是不可破**：OpenList 用「官方 token + 伪装客户端 UA(netdisk)」实现百度全盘挂载。代价是灰色地带与长期维护债务 | §9.2 |

## 2. 百度网盘：能力与约束

### 2.1 接入路径（可行）

```
实名认证（个人开发者，即时审核）
  → 控制台创建应用（应用用途选【个人使用】→ 免审核、直接上线、限 10 个用户）
  → 拿到 AppId / AppKey / SecretKey / Signkey
  → OAuth 授权（三选一）
       · 授权码模式：需 redirect_uri（可配 oob 或自定义 scheme）
       · 简化模式：无 refresh_token，过期需重新授权（不推荐）
       · 设备码模式：无服务器场景推荐，用户在浏览器输码授权，应用轮询取 token
  → access_token（授权码模式有效期 30 天）+ refresh_token（10 年），过期自动续期
```

上传三段式：

| 阶段 | 接口 | 作用 |
|------|------|------|
| 预上传 | `POST /rest/2.0/xpan/file?method=precreate` | 提交目标 path、size、`block_list`（各分片 MD5）。**命中秒传时返回 `return_type=2`，跳过第二阶段** |
| 分片上传 | `POST https://d.pcs.baidu.com/rest/2.0/pcs/superfile2?method=upload&type=tmpfile&partseq=N` | 逐片上传，单片固定 4MB（末片可小于），片数 ≤ 1024 |
| 创建文件 | `POST /rest/2.0/xpan/file?method=create` | 合并分片并发布到目标路径；同名策略由 `rtype` 控制（1 不重命名 / 2 重命名 / 3 覆盖） |

### 2.2 硬约束与影响

| 约束 | 具体 | 对本项目的影响 | 应对 |
|------|------|--------------|------|
| **沙箱目录** | 只能写 `/apps/{应用名}/`，用户视角为「我的应用数据/{应用名}」 | 用户不能指定网盘任意目录；已在 UI 上暴露"输出目录"的语义要改 | 设置页提示实际落盘位置；路径自动加 `/apps/{appname}` 前缀 |
| **单文件大小** | 普通 4GB / 会员 10GB / 超会 20GB；片数 ≤ 1024 | 单段 4K 视频（>4GB）会失败 | 执行前按大小预检，超限文件直接进失败清单并给明确原因 |
| **类型限制** | 官方提到普通用户在网盘 APP 端无法上传视频、Live Photo | 若 API 端同样受限，照片备份里的视频会失败（本项目支持 mp4/mov 等） | **必须实测**（见 §7） |
| **频率限制** | 官方有调用频率限制，具体数值需查文档 | 逐文件 Exists 检查会放大请求数 | 目标目录预枚举缓存 + 令牌桶限流 |
| **凭证归属** | AppKey/SecretKey 属应用，不可内嵌分发 | 开源分发即泄露 | 设置页由用户自填；SecretKey 走 `ICredentialCrypto` 加密存储 |

### 2.3 授权在双端的落地差异

| 端 | 方案 | 备注 |
|----|------|------|
| Desktop | 系统浏览器打开授权页 + 本地 loopback（`http://127.0.0.1:PORT/callback`）捕获 code | 需在控制台把 loopback 地址配进 redirect_uri 白名单 |
| Android | 自定义 scheme `moauth://baidu-callback` + `intent-filter` 的回调 Activity；或用设备码模式（免回调） | 需新增一个轻量回调 Activity；Custom Tabs 需引入 `AndroidX.Browser` |
| 两端共同 | Token 存储复用现有 `ICredentialCrypto`（Windows DPAPI / Android Keystore）；access_token 过期前自动用 refresh_token 续期 | 已有基础设施，改动小 |

## 3. 夸克网盘：不可行

| 核查项 | 结果 |
|--------|------|
| 官方开放平台 | `open.quark.cn` 面向**夸克小程序**与 AI 能力，**无网盘 API 入口** |
| OAuth / AppKey 申请 | 无 |
| 接口文档 | 无官方公开文档 |
| 社区方案性质 | 全部为 Web/App 端逆向：`drive-pc.quark.cn/1/clouddrive/...`，依赖登录 Cookie、设备指纹、动态签名（HMAC/时间戳/nonce），Token 短时效 |
| 合规 | 违反《夸克用户协议》关于禁止自动化访问的条款；账号有风控封禁风险 |
| 适配性 | 社区方案主要是「分享链接转存」，不是「上传本地文件」，与本场景不符 |

**结论：放弃。** 逆向接口即使短期可用，也会在签名算法或风控升级时突然失效，而本项目是需要长期可靠运行的备份工具——不可接受。

> 补充：即使在 OpenList 里，夸克也是最差的一档（官方声明不维护、强制本地代理中转、需会员、TV 驱动不支持上传），详见 §9.3。

## 4. 第四个目标选谁

| 候选 | 可行性 | 说明 |
|------|--------|------|
| **S3 兼容存储**（自建 MinIO / 腾讯云 COS / 阿里云 OSS / Cloudflare R2） | 高（推荐） | 标准协议、官方 SDK 成熟、无私有 API 变更风险、可自建、支持分片与断点续传。缺点：多数为按量计费，非"免费网盘" |
| WebDAV（坚果云等） | 已支持 | 零开发成本，直接复用现有 `WebDavFileStorage` |
| 115 网盘开放平台 | 中 | 有官方开放平台与上传接口，需自行注册核验当前政策 |
| 天翼云盘 / 和彩云 | 中 | 有开放平台，政策与配额需核实 |
| 阿里云盘 | **需核实** | `alipan.com/developer` 提供 OAuth 第三方接入（OpenList 等在用），但**个人开发者能否创建应用、是否对个人应用开放写入**未在公开文档中确认，需要你自行尝试注册验证 |
| ⚠️ 网盘与相册服务 PDS | 不适用 | 这是阿里云**付费的 PaaS 产品**（有 domain_id / drive_id、需开通计费），用于自建网盘服务，**不是**把文件传到用户个人阿里云盘的通道。选型时别混淆 |
| 夸克网盘 | 不可行 | 见 §3 |

战略建议：私有网盘 API 每接一家都是长期维护负担（接口变更、限流、风控）。**优先用标准协议覆盖异地备份需求**，百度网盘作为"用户已有大容量会员"场景的补充。

## 5. 架构改造评估

### 5.1 `IFileStorage` 与网盘 API 的语义错配

现状接口（7 个方法）是按「文件系统」建模的，网盘 API 有 5 处对不上：

| 现有方法 | 网盘 API 现实 | 改造建议 |
|---------|--------------|---------|
| `ExistsAsync(path)` | 每文件一次 HTTP 请求；网盘有 QPS 限制 | **下推同名策略**：百度 `create` 的 `rtype` / 阿里 `check_name_mode` 原生支持"跳过/覆盖/重命名"，可省掉预先 Exists；或按目录预枚举建索引 |
| `CreateDirectoryAsync(path)` | 网盘创建目录是独立接口且通常只能逐级创建 | 复用 `WebDavFileStorage._knownDirs` 的缓存模式；阿里云盘还需维护「路径 → file_id」映射缓存 |
| `CopyFromAsync(src, target)` | 三段式（precreate → 分片 → create），**本身就是原子的**：未 `create` 前文件不出现在网盘 | **新增能力标志 `SupportsAtomicWrite`**，`FileOperator` 据此跳过 `.mo-tmp` + `MoveAsync` 流程，直接写最终名——反而更快更安全 |
| `GetLengthAsync(path)` | 需要额外一次 `meta`/`list` 请求 | 用 `precreate` 提交的 size 与 `create` 返回值自证，省掉这次请求 |
| `DeleteAsync` / `MoveAsync` | 阿里云盘的删除/移动是**异步任务**（返回 `async_task_id`，需轮询） | 接口语义需允许"发起后不保证立即可见"，或在实现内部轮询完成后再返回 |
| `SetModifiedUtcAsync(path, utc)` | 两家都不支持写 mtime | 沿用 `WebDavFileStorage` 的 no-op 先例 |
| —（新增） | 网盘需要**限流** | 新增 `IFileStorage` 可选能力或独立 `IRateLimiter`，`FileOperator` 在并发循环里过令牌桶 |

> 好消息：这些改造里，"跳过 `.mo-tmp`" 和 "预枚举索引" 正好与上一份评估（SMB 提速 M3）是**同一批改动**，可以一起做、一起受益。

### 5.2 配置模型与 UI

| 改动点 | 内容 |
|--------|------|
| `NetworkType` 枚举 | 新增 `BaiduNetdisk`（`Enums.cs:13`）。`NetworkProfileVM.TypeLabel`（`SettingsViewModel.cs:37`）与 `NetworkTypeOptions`（`:94`）同步扩展 |
| `NetworkProfile` 模型 | 现状只有 `Name/Type/Address/Username/Password`。OAuth 需要 `AppKey`、`SecretKey`、`AccessToken`、`RefreshToken`、`TokenExpiresAt`、`AppName`（沙箱目录名）。建议新增 `OAuthConfig` 子对象，避免污染现有字段 |
| 配置版本 | `AppConfig.CurrentVersion = 1` 且**当前无任何版本迁移逻辑**（`AppConfig.cs:35`）。新增字段属于向后兼容的加法（旧配置反序列化时取默认值），风险可控，但应把版本号提到 2 并补一次空迁移骨架 |
| 加密 | SecretKey / RefreshToken 必须走 `CredentialCrypto`（DPAPI / Keystore），**不得明文落 config.json**（NFR-A10 / FR-A10.4：日志与报告严禁出现凭据） |
| 设置页 | 新增"百度网盘"类型；表单增加 AppKey/SecretKey/应用名 三项；新增「授权」按钮（打开浏览器完成 OAuth）；连接测试改为"token 有效性 + 沙箱目录可写"探测 |
| `StorageFactory.CreateProfileStorage` | 新增分支（`StorageFactory.cs:107`） |
| 测试连接 | `StorageFactory.TestConnectionAsync` 的探针逻辑可复用，但网盘下要改成写 `/apps/{appname}/.mo-test/` |

### 5.3 传输时长预估（20GB / 5000 文件，同一批数据）

| 场景 | 有效吞吐 | 预估时长 | 说明 |
|------|---------|---------|------|
| 局域网 SMB（现状） | ~25 MB/s | **≈ 16 分钟** | 上一份评估的基线 |
| 网盘全量（宽带上行良好、无限速） | 5 MB/s | ≈ 68 分钟 | 家庭上行 40Mbps 的理想值 |
| 网盘全量（限速或弱网） | 0.5 MB/s | ≈ 11 小时 | 网盘对第三方 API 常有限速，**必须实测** |
| 网盘全量（手机 4G） | 1 MB/s | ≈ 5.6 小时 | 且耗流量 |
| **网盘增量（命中秒传）** | 本地 MD5 + 2 次 API/文件 | **≈ 15~20 分钟** | 5000 × (MD5 计算 + 2 次请求) |

→ 网盘方案的价值不在"快"，而在**异地容灾 + 增量近乎免费**。首次全量会很慢，需要明确管理用户预期（UI 上显示预估剩余时长与"建议在 WiFi 且充电时执行"）。

### 5.4 秒传的适配性

百度 `precreate` 提交 `block_list`（各分片 MD5）后，若服务端已存在相同内容，返回 `return_type=2` 直接完成，无需上传数据。

- 本项目是**原样复制**（不改码、不改写 EXIF），内容哈希稳定 → 第二次备份同一批照片命中率接近 100%
- 代价：每个文件要完整读一遍算 MD5。20GB 在手机上约 1~3 分钟，相对上传时长可忽略
- 前置条件：`ExistAction` 选 Skip 时才有意义（覆盖策略会强制重传）

## 9. 补充调研：OpenList 这类项目如何实现「全盘访问」（修正 §2.2）

> 这一节修正前文结论。§2.2 说"百度只能写 `/apps/{应用名}/` 沙箱"——**那是用应用身份按官方文档调 API 的结果**。OpenList / AList 确实能挂载百度网盘全盘（`/` 根目录，含隐藏空间、共享目录），做法是另一条路。

### 9.1 四类手段

| 层次 | 做法 | 能达到的效果 | 代表 |
|------|------|------------|------|
| **L1 官方 API（守规矩）** | 自己建应用 → OAuth → 按文档调开放平台接口，应用身份明确 | **仅 `/apps/{appname}/` 沙箱**、受单文件/类型限制 | 本项目若直接接百度官方 API |
| **L2 官方 token + 伪装客户端** | 仍用开放平台的 access_token，但把 UA 等客户端标识伪造成官方客户端（`netdisk`），走客户端接口域名 | **全盘访问**，且绕开部分限速 | **OpenList 的百度网盘驱动** |
| **L3 纯逆向，用户自带凭证** | 抓包 Web/App 接口，用浏览器复制的 Cookie 或扫码登录拿到的 token | 全盘，但无文档、需手动续期、随时失效 | 夸克、移动云盘、天翼云盘、115 等 |
| **L4 逆向 + OAuth 外壳** | 有 AppID/SignKey 与 OAuth 流程，但官方无文档、不承诺稳定 | 部分能力，且明确"并非真正意义上的开放接口" | 夸克 Open 驱动 |

**关键洞察：没有任何一家网盘是靠"守规矩的官方 API"实现全盘访问的。** 全盘访问 = 伪装官方客户端（L2）或纯逆向（L3）。

### 9.2 百度是怎么绕开沙箱的

OpenList 百度网盘驱动的配置项暴露了机制：

- **「自定义破解 UA」默认值 `netdisk`** —— 把 User-Agent 伪造成官方客户端
- **「上传 API」`https://d.pcs.baidu.com`** —— 官方客户端的分片上传域名（与开放平台 `superfile2` 同一套）
- **「线程 ≤32」「每切片上传超时秒数」** —— 模拟客户端的并发分片行为

服务端是按**应用身份**施加沙箱策略的：官方客户端的 `app_id` 不受"第三方应用只能写 `/apps/`"这条规则约束。换个 UA 和标识，服务端就按客户端待遇放行。

> 本质上是寄生在官方客户端协议上。只要网盘方加强校验（请求签名、设备指纹、证书绑定），这条路就会断。百度目前宽松到只改 UA 即可，属于"没认真拦"。

### 9.3 夸克：即使在 OpenList 里也是最差的一档

OpenList 官方文档对夸克驱动的原话（doc.oplist.org）：

> 本接口是基于历史产物的逆向接口，项目组不会主动进行维护，请勿针对此驱动提出有关于任何修复或进行进一步逆向行为需求的 issue。

并且：

- **强制本地代理**：「由于夸克网盘限速问题，夸克网盘现在只能使用本地代理进行传输」——数据必须先落到 OpenList 服务器再转发，服务器带宽决定速度
- **需要会员**：「夸克云盘下载很慢是因为夸克云盘需要开通会员」
- **Quark Open 驱动**官方标注「该"Open"并非真正意义上的开放接口，不提供进一步的教程」
- **Quark TV 驱动**只支持访问与下载，**不支持上传**
- 上传实现需 `CacheFullInTempFile()` 把**整个文件先落临时文件**再算 MD5/SHA1 → 对手机端 4GB 视频是灾难

→ 夸克的结论不变（不可行），但理由升级：不是"没有 API"，而是"只有逆向接口、官方不维护、强制中转、需会员"。

### 9.4 对本项目的含义

**选项 A：照 OpenList 的方式自己接（L2/L3）**

- 技术上可行，百度全盘可达
- 但要自己长期跟进逆向变更，且明确处于**灰色地带**（违反网盘用户协议）
- 公开资料反复警告风控后果：限速、限制登录、封号（社区建议"用小号挂载"）
- 成本：与 §6 估算相当，另加**长期维护债务**

**选项 B：不自己接，用 OpenList 做中转（推荐）**

```
MediaOrganizer ──WebDAV──> OpenList（常驻：NAS / 家用机 / 云服务器）
                              └──> 百度（伪装客户端，全盘）
                              └──> 夸克 / 115 / 天翼 / 移动云盘 / 阿里云盘 …
```

- **零新代码**：`WebDavFileStorage` 已实现，直接填 OpenList 的 WebDAV 地址即可
- **一次接入覆盖几十种网盘**，且网盘适配的维护负担外包给 OpenList 社区
- 沙箱、秒传、分片、限速应对全部由 OpenList 处理
- 代价：① 需要一台常开的机器跑 OpenList；② 手机要能访问到它（局域网 / VPN / 内网穿透）；③ 上传路径变两段（手机 → OpenList → 网盘），在家连 NAS 时总速度受两段中最慢的制约

> 若你家里已有 NAS，选项 B 的成本几乎为零，且立刻可用。这也顺带解决了"夸克能不能用"——能用，但如前所述体验最差。
