# ADR-0002: C# 版功能范围（精简清单）

- 状态：已接受（Accepted）
- 日期：2026-08-08
- 依据：ADR-0001，grill-with-docs 访谈结论

## 背景

Python 版约 26 个源文件、总计约 55 万字节源码，其中 GUI/魔术工具/配置编辑器占比超过 60%。迁移目标是开源发布的 Avalonia 桌面应用，几万张照片规模、个人与小众用户使用。

## 决策：保留 / 简化 / 删除

### 保留（核心闭环）

1. 扫描 + 扩展名过滤（`supported_formats`，含 scan_all_files 开关）
2. 三级提取器加权链（见 ADR-0003）：EXIF 1.2 > 文件名 1.1 > mtime 0.8（默认禁用）
3. 文件名正则模式体系 + 快速年份扫描优化
4. 日期范围校验（`max_years_past` / `future_date_buffer_days`，1970–2100 硬边界）
5. 分析 → detail/unparsed JSON → TXT 分析报告
6. 年/月/日分级目录 + **copy / move** + skip / overwrite / rename
7. 未来日期归入 `FutureDate/`
8. 失败文件列表 + 图片预览 + **批量移动到待处理文件夹**
9. **魔术工具完整移植**：字符着色、交互式点选生成正则、结构指纹、多变体智能正则、实时测试、保存到 patterns（差异化卖点）
10. 配置编辑器 4 个 Tab 完整移植（提取器 / 文件名模式 / 系统 / GUI）
11. 文件 mtime 矫正开关（整理后便于资源管理器排序）

### 简化

| 功能 | 简化方式 |
|------|----------|
| 并行处理 | 砍掉多进程层，用 `Parallel.ForEachAsync`（I/O 密集天然适合 async），无进程池/临时日志合并/回退逻辑 |
| 多语言 | 文本全部外置到资源文件，首发只写中文资源，结构预留英文位 |
| 视频处理 | 不内嵌播放器，双击调系统默认应用打开；视频日期只读容器元数据 |
| 日志 | 只保留内存日志（上限 1000 条）+ TXT 报告 |

### 删除

| 功能 | 删除理由 |
|------|----------|
| 多进程层（multiprocess_*，~44KB） | C# 并行模型完全不同，Python 那套是语言限制下的 workaround |
| SQLite 详细模式 + MD5 指纹 + 去重 + 导出 | 几万张规模用不上，开源后有真实需求再加（ADR 留扩展位） |
| link 操作（硬链接/符号链接） | Windows 权限坑多、跨平台行为不一致，copy 已覆盖需求 |
| 元数据编辑（写 EXIF / PNG 文本块 / 视频 ©day） | 用户明确不要；失败文件走"加规则重扫"路线 |
| 日期调整面板（年月日时分秒输入 + 保存同步） | 随元数据编辑一并移除 |
| 手动指定日期纳入整理 | 同上；补救路径 = 魔术工具加规则 → 重新分析 |
| 正则模式分析报告 | 开发期工具，运行时价值低 |
| 内嵌视频播放器 | 系统应用打开替代 |
| HEIF 专用提取器 | 被 ImageMagick 统一吸收 |

## 后果

- GUI 主界面从三栏缩为两栏：上方操作区 + 下方文件列表/预览。
- 失败文件的唯一补救路径是迭代正则规则，因此魔术工具成为一等公民（与"完整保留"决策自洽）。
- 数据格式（config/patterns/detail/unparsed JSON）全部重新设计，不与 Python 版兼容；patterns 的规则内容可人工迁移。
